# 自定义版

本分支是 [w1718w](https://github.com/w1718w) 在
[上游 Dolce](https://github.com/lodebar2026/dolce) 基础上的二次开发版本。上游已有功能、使用方法与格式说明仍以原文档为准；
本页只记录自定义版额外增加或改变的内容。

## 转记与预设

**转记不改变实际音高**，只换同一批音的记法；与移调是两件事。入口是谱面编辑菜单的「转记…」，
一次处理整份文档，不按选区分段。对话框可选择目标 `1=?`、临时半音的拼写规则与预设。

- **目标调号**取五度圈 `-7..7`。曲中的转调统一收束到这个调号，再按原调号读出每个音的实际音高，重算唱名、八度与临时升降号。
- **临时半音**可跟随目标调号，或统一用升号 / 降号。统一升降号只决定同音异名的写法，不升高或降低音高。
- 内置「半音阶推键」预设：转记为 `1=C`，临时半音统一用升号，便于按半音阶推键演奏。
- 内置「常规固定 C」预设：转记为 `1=C`，临时半音跟随调号。
- 可保存自定义预设；预设只存在本机设置里，不写进乐谱文件。
- 所有歌曲、声部、声线、和弦音与倚音都会处理；和弦记号文字不改。整次操作可一步撤销，同一选项重复执行不会继续改变结果。

支持 123、ABC、JP-Word、文本谱、jianpu-ly、Muse 简谱与 MusicXML。文本格式仍由各自原有的写出端写回；
MusicXML 走模型编辑。

## 自定义功能接入

转记模型变换集中在 `src/model/transcribe.ts`，编辑器执行、预设校验、对话框与写回集中在
`src/editor/transcription.ts`。可视化编辑控制器只保留命令转交与设置接入。
后续自定义功能优先放进独立模块，接入时尽量只新增代码，保留上游原有导入行和方法签名，以减少同步冲突。
上游若修改共用接口，仍需检查构建与功能行为。

## 分支与发布

- `main` 跟随上游，不放自定义功能。
- `custom/main` 是自定义版主线，也是本仓库的默认分支；从 `main` 合并上游更新。
- 自定义版标签使用 `v<上游版本>-custom.<修订号>`，例如 `v0.8.2-custom.1`。源码里的基础版本号仍跟随上游。
- 旧标签 `v0.8.2-fork.1` 保留，不改名；以后不再使用 `-fork.N`。

## 同步上游

同步由 `.github/workflows/sync-upstream.yml` 的 **Sync upstream** 工作流负责，不再依赖 Pull App。
每六小时检查一次，也可以在 Actions 页面选择该工作流，点击 **Run workflow** 手动执行。

1. 将 `lodebar2026/dolce:main` 快进同步到本仓库的 `main`。若两边历史分叉则报错停止，不强制覆盖。
2. 若 `custom/main` 尚未包含这些提交，创建或复用 `main → custom/main` 的 PR。
3. 工作流对当次记录的两个提交尝试合并并运行 `npm ci`、`npm run build`；冲突或构建失败会显示在 Actions 中。
4. 检查通过后，在 PR 中选择 **Create a merge commit** 合入。不要 squash 或 rebase，否则下次同步可能重复引入上游提交。工作流不会自动合并或发布。

首次启用：将工作流提交到默认分支 `custom/main`，确认仓库 Actions 已启用，并在
Settings → Actions → General → Workflow permissions 勾选 **Allow GitHub Actions to create and approve pull requests**。
若分支保护限制 `main` 写入，需要允许此工作流的同步方式。停用该仓库的 Pull App，避免旧配置与新任务同时操作分支；
旧的 `.github/pull.yml` 已在自定义分支删除，但镜像 `main` 仍可能包含它。
工作流使用仓库自带的 `GITHUB_TOKEN`，无需额外保存个人令牌。合并与构建验证在同步工作流内显式执行，
是否触发 PR CI 不影响这一步；应核对 Actions 中验证的提交是否仍是 PR 当前版本。
定时任务可能延迟；公开仓库长期无活动时也可能被 GitHub 停用，可在 Actions 页面重新启用。

自动任务不可用时，可以在本地干净工作区执行（已有 `upstream` 远程）：

```sh
git fetch upstream
git fetch origin
git switch main
git merge --ff-only origin/main
git merge --ff-only upstream/main
git push origin main
git switch custom/main
git merge --ff-only origin/custom/main
git merge origin/main
npm ci
npm run build
git push origin custom/main
```

遇到冲突时先解决、暂存并完成合并提交，再构建；若暂不处理，执行 `git merge --abort`。
任一步失败都应停止，不要继续后面的推送。此操作只同步代码，发布仍沿用自定义版标签流程。
